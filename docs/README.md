# Govern knowledge base

The project's knowledge base, used for RAG. Every document has front matter (title, tags, code paths, updated date) and covers one topic. The writing rules are in `.claude/rules/docs.md`.

## Architecture
- [architecture.md](architecture.md): layers, allowed references, request flow, folder templates (UF / AGFT / 3DFT), naming rules and how they are enforced.

## Features
- [features/game-core.md](features/game-core.md): the pure game engine in `Govern.Core`: every number from the ruleset (`Ruleset`, a parameter of every entry point), hex map, units and abilities, combat (health as damage, `CombatCalculator`, the forecast, healing), cities, builders, improvements, buildings and bridges (`Core/Economy`, unit jobs), tile yields (`YieldCalculator`), city territory (`TerritoryRule`) and each city's stock, commands and rules, error codes, fog of war (`PlayerView` with row-major tiles, and hidden enemy production and movement), view-based previews for the client, the opaque view version, random ids, determinism and the JSON format (schema v3).
- [features/games.md](features/games.md): games and lobby: phases, `/api/games` endpoints and status codes, sending commands (opaque per-player `expectedVersion`, rule-violation codes), live updates over SSE (`/stream`, heartbeat, push on visible change), lobby leave/cancel and 7-day expiry, the list's `activityAt`, error codes, per-user rate limits, caps and the rolling 24-hour quota, invite codes, per-game player ids (no user ids exposed), join/start/command races, `games`/`game_players` tables and the `jsonb` state.
- [features/game-ui.md](features/game-ui.md): the game UI design system (G1): screen zones (top bar, map, action bar, side panel), interaction rules (select then act, two-step attack with the combat forecast, inline confirm, tooltips, keyboard), `GameUiService`, design tokens and light/dark themes, the `GameSprite` icon set, board layer order, the component catalog (built and planned), map lenses (`IMapLens`, `LensToolbar`, `BoardLens`, movement cost), rivers, bridges, the improvements and territory borders layers, the yields lens, bridge mode, the cities' resources in the top bar and the city's stock in its panel, the `/design` gallery, and how a new mechanic adds its UI.
- [features/client.md](features/client.md): Blazor WASM client architecture (CFT feature folders), `Api:BaseUrl` configuration, authentication (token store, refresh ahead of expiry and on 401, cross-tab Web Lock, login/register/profile pages, login redirect), typed clients and `ApiError`, the game lobby (`/games`, `/join#<code>` invite links, live game page with SSE reconnect and backoff), the game board (SVG hex map with pan and zoom, selection and highlights from the Core previews, commands one at a time with stale-version reload, game over), CSP and security headers on the Static Web App, release-time configuration, bUnit and architecture tests.
- [features/users.md](features/users.md): sign-up, sign-in, refresh token rotation and reuse detection, session cap and cleanup, sign-out, current user; endpoints, errors, data model.

## Game design

- [game/rules.md](game/rules.md): the game rules reference for players (G2): goal and victory, the map (generated, mirrored halves), terrain types (movement cost, passable, sight and defence bonus), rivers (crossing, defence bonus), turns and rounds, unit types (class, strength, ranged strength, build production) and abilities, moving, attacking and capturing cities, combat (health, damage, class counters, healing), founding cities, production, building with units, tile yields, territory, city resources, improvements, bridges, city buildings, costs and upkeep, fog of war, and the game numbers; its tables are checked against the ruleset by `RulesReferenceTests`.
- [game/game-data.md](game/game-data.md): the loadable ruleset (`rulesets/default/v7.json`, read by `Govern.Core/Rulesets`): the boundary between data and Core logic, lifecycle (JSON in the repo, stored per version, pinned per game, served to the client; storing and pinning deferred), the database record, reading it in code (`Ruleset.Parse`, strict JSON, the hash), format conventions, every section with its fields, defaults and examples (setup, map, map and river generation, terrains with sight and defence bonus, rivers with crossing cost and defence bonus, units with class, strength, ranged attack, build production and abilities, cities, territory, upkeep, combat, texts), validation rules with JSON paths.
- [game/game-data-economy.md](game/game-data-economy.md): the ruleset's building and economy sections (G10a, G5, G7, G8a): terrain and river `yields`, `cities.yields`, `cities.startingStock`, `territory`, unit and building `resourceCost` and `upkeep`, the `upkeep` section, `bridges`, `resources`, `improvements`, `buildings`, `units[].buildProduction`, with examples and their validation.
- [game/game-logic.md](game/game-logic.md): draft: Core's algorithms as simple steps: creating a game (map and river generation), executing a command (guard, apply, victory, explore), move (with river crossings), attack, combat (strength, counters, terrain, river, damage roll), found city, set production, produce a building, build an improvement or a bridge, set the upkeep priority, unit jobs at the end of a turn, territory growth, end turn (jobs, city income, upkeep and healing, territory, resource costs and production), costs and upkeep (paying order, supply off territory, shortage damage, building health), resign, elimination and victory, fog of war and the view version, view previews, randomness and ids, invariants, with the ruleset key for every number.
- [game/design-roadmap.md](game/design-roadmap.md): future game mechanics (G1–G15), what each one is (priorities are in the backlog): the UI design system, a game rules reference, data-driven catalogs (ruleset A done, B deferred), terrain layers, resources and tile yields, rivers and bridges, city territory, stats and production queue, unit roster and combat, builders and buildings with upgrades, science and culture trees with upkeep, civilizations and governors, colonies founded by governors, seasons, ships and river navigation; the decisions taken and open questions (diplomacy, texts and languages, the game logic doc).

## Plans
Priorities live only in the backlog. Plans sit in `active/`, `deferred/` or `done/` by state.
- [plans/backlog.md](plans/backlog.md): **all open work**, prioritised in buckets (Now, Next, Deferred, Ideas) with stable ids: content slice C1 (rules reference G2, terrain G4, units and combat G9), rivers G6, builders and buildings G10a, tile yields G5, territory G7 and city costs and upkeep G8a done, the game log and board animations (F11a, F11b) done, Now empty until the owner picks; next player-chosen city names and the scale-out backplane; deferred rulesets in the database (G3b), the other game mechanics (G8b, G10b, G11–G15), shipping the game and the release follow-ups, simultaneous turns, more players and diplomacy.
- [plans/done/G5-G7-G8-economy.md](plans/done/G5-G7-G8-economy.md): G5, G7 and G8a (done, PR #34 and PR #35) plan (owner's model): tile yields with water and desert, city territory grown with culture, each city's own stock, then resource costs paid when production begins, upkeep with a per-city priority, supply from the 7 tiles around a unit outside territory, shortage damage down to 1 HP and building health; two PRs, ruleset v6 and v7.
- [plans/done/F11a-game-log.md](plans/done/F11a-game-log.md): F11a (done, PR #37): engine events filtered per player by visibility (`VisibilityCalculator.EventsFor`), per-seat log storage, the recent log in game snapshots, and the side panel log.
