# Persistence (EF Core + PostgreSQL)

## Access pattern

- Handlers inject `IApplicationDbContextFactory` and create **one context per operation**:
  ```csharp
  await using var db = await dbContextFactory.CreateDbContextAsync(cancellationToken);
  ```
- `IApplicationDbContext` exposes only `DbSet`s, `SaveChangesAsync` and `BeginTransactionAsync`. Adding an entity means adding its `DbSet` there **and** in `ApplicationDbContext`.
- Use `BeginTransactionAsync` only for work that spans several `SaveChangesAsync` calls. A single save is already atomic.
- No generic repositories. A repository exists only for cached queries (see `architecture.md`).

## Queries

- **Reads:** `AsNoTracking()` plus a projection into a response or model (`mapping.md`). Load entities (tracked) only when you are going to change them.
- Filter, sort and page in SQL, before `ToListAsync`. Put a maximum on page size.
- **Filtered includes** load only what a use case needs: `.Include(u => u.RefreshTokens.Where(t => t.RevokedAt == null))`.
- **Bulk changes:** `ExecuteUpdateAsync` / `ExecuteDeleteAsync`. These bypass interceptors, so no audit stamps or domain events.
- Never lazy loading, never raw SQL string concatenation (`FromSql($"...")` is parameterised and allowed).

## Model and configuration

- Entities derive from `BaseEntity` or `BaseAuditableEntity` (arch test).
  - Ids are Guid v7, generated by the domain. `ApplicationDbContext` sets `ValueGeneratedNever()` for all entities, so new children added through navigations are inserted.
  - Domain events are ignored by the model.
- Mapping goes in `Persistence/Configurations/XxxConfiguration.cs` (`IEntityTypeConfiguration<T>`), never in attributes on entities. The Domain has no EF dependency (arch test).
- **Naming:** snake_case tables, columns and constraints come from `UseSnakeCaseNamingConvention()`. Don't hard-code table names.
- **Columns and indexes:** every string gets a max length; unique business keys get unique indexes (email, token hash); foreign keys get indexes.
- **Collections:** backing fields with `UsePropertyAccessMode(PropertyAccessMode.Field)`. Aggregates change children only through methods on the root.
- **Value objects:** map a single-value object (e.g. `Email`) to one column with `HasConversion(vo => vo.Value, value => Vo.Create(value))` plus `HasMaxLength` in the owning configuration (example: `UserConfiguration`). In queries, compare value object to value object (`user.Email == email`) so EF applies the converter; never use `.Value` inside `Where`. Reading `.Value` in the final `Select` is fine. Because `Create` re-validates on every read, tightening a value object's rules is a data change: before release, check (read-only SQL) that no stored row breaks the new rules, or migrate the rows. A normalising `Create` must be idempotent (`Create(Create(x).Value) == Create(x)`), and a unit test must prove it.
- **Races:**
  - For check-then-act on a row (e.g. single-use tokens), mark the state column `IsConcurrencyToken()` and translate `DbUpdateConcurrencyException` into an `Error` (example: `RefreshTokenConfiguration` + `RefreshTokenHandler`).
  - For uniqueness, keep the `AnyAsync` pre-check (friendly error) **and** catch `DbUpdateException` when `IDbExceptionClassificationService.IsUniqueViolation(...)` (example: `SignUpHandler`).
  - Cover both with a concurrent integration test (`Task.WhenAll`).

## Interceptors (automatic)

- `AuditableEntityInterceptor` sets `CreatedAt` / `UpdatedAt` from `TimeProvider`. Never set them by hand.
- `DispatchDomainEventsInterceptor` publishes domain events after a successful `SaveChangesAsync`. A synchronous `SaveChanges` with pending events throws.
  - Delivery is **best-effort**: the data is already saved, so a failing handler is logged (EventId 2001) and does not fail the request. Handlers also run without the request's cancellation token.
  - Inside an explicit `BeginTransactionAsync`, events fire on each save, **before** the transaction commits. Don't send irreversible side effects (emails) from events raised inside explicit transactions.
  - When an event must never be lost, use an outbox in `Infrastructure/Background/` (not built yet).

## Migrations

- Create a migration with:
  ```bash
  dotnet ef migrations add <PascalCaseName> --project src/Govern.Infrastructure --startup-project src/Govern.Api --output-dir Persistence/Migrations
  ```
  - It needs `ConnectionStrings__Govern` and `Jwt__SigningKey` set (user-secrets or environment variables). No database connection is made.
- Never hand-edit `*.Designer.cs` or the model snapshot (a hook blocks it). Fix the model and regenerate with `dotnet ef migrations remove` + `add`.
- Review the generated `Up`/`Down` before committing: renames that became drop+add, data loss, lock-heavy operations.
- Migrations are applied at startup by `DatabaseMigrationService` (`Database:MigrateOnStartup`). A failed migration stops the app.
- Migrations are generated code: `.editorconfig` marks them `generated_code`, and size limits skip them.

## Testing

Persistence behaviour is covered by integration tests against real Postgres (Testcontainers). Assert persisted state through `GovernApiFixture.OpenDbAsync()`.
